# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Go library (module `github.com/nagylzs/pgxrepmgr`, single package `pgxrepmgr` at the repo root) that discovers and monitors a PostgreSQL repmgr cluster by reading `repmgr.nodes`, or monitors the nodes that a caller's `NodeSource` lists (then the cluster needs no repmgr). It gives callers the current primary node and the nearest node (lowest connect latency), plus cached pgx pools for them. Dependencies: `jackc/pgx/v5` and `teivah/broadcast`.

## Commands

```sh
go build ./...                         # build the library and the watch program
go vet ./...                           # vet everything
go test ./...                          # unit tests, no database needed

go test -tags integration -v ./testenv # integration tests; they start the docker test cluster if needed
testenv/cluster.sh up                  # start the docker test cluster (no arguments: list all commands)
go run ./testenv/watch -write          # run a Connector against it and print every primary/nearest change
testenv/cluster.sh down                # remove the cluster and its data
testenv/plain.sh up                    # start a new test cluster without repmgr (no arguments: list all commands)
```

CI runs on GitHub Actions. `.github/workflows/ci.yml` runs on every push and pull request: gofmt, `go vet` (with and without the `integration` tag) and `go test -race ./...` on Go 1.25 (the minimum in `go.mod`) and the current release, plus staticcheck and govulncheck at pinned versions. `.github/workflows/integration.yml` runs the integration tests on pushes to `main` and by hand (`gh workflow run integration.yml`), not on pull requests, because the failover tests depend on timing.

`go test ./...` runs only the unit tests, which need no database (`*_test.go` at the root). They use seeds where nothing listens (`closedPort`) or where a server accepts connections and never answers (`hangingServer`). `source_test.go` tests the `NodeSource` mode with `testSource`, whose list and error the test changes, and nodes at closed ports (`listed`). The integration tests in `testenv/` need the `integration` build tag.

## Test environment (`testenv/`)

`testenv/compose.yaml` runs three PostgreSQL 17 nodes with repmgr 5.5 and repmgrd (automatic failover). They are node1 `172.28.0.11` (the initial primary), node2 `.12` and node3 `.13` (lower priority). The nodes register in `repmgr.nodes` by IP address, and on Linux the host reaches those addresses directly, so Go code under test runs on the host with no port mapping. Credentials are `repmgr`/`repmgr` (the `watch` default) and `app`/`app`. Database `app` has a `writes` table whose `node` column defaults to the name of the node that accepted the insert. A fresh `up` takes about 25 seconds.

`cluster.sh` is the interface to the cluster: `show` prints each node's own copy of `repmgr.nodes` (which is what the connector reads), plus its recovery state, timeline and write count. `isolate <node>` uses iptables inside the node to cut it off from the other nodes while the host can still reach it, and `heal` undoes that. It resets TCP connections instead of dropping them, because with DROP, open connections hung: a repmgrd stuck on one missed the failover, and after `heal` a standby received WAL from the old primary and could no longer follow the new one. `repair` keeps the node on the highest timeline as primary and rejoins every other node that doesn't stream from it within 15 seconds. `delay <node> <ms>` adds latency with netem. `stop`/`kill`/`start` stop a node cleanly, crash it, or start it again. `rejoin <node> <primary>` turns a former primary into a standby with pg_rewind.

`up` leaves a running cluster as it is. After you change the `Dockerfile` or `node-entrypoint.sh`, use `up --build`, which recreates the nodes. Each build gets a new image ID even when nothing changed, which is why `up` doesn't rebuild every time.

`testenv/plain.yaml` runs a second cluster without repmgr, from the same image with its own entrypoint (`plain-entrypoint.sh`, mounted, so no rebuild is needed): plain1 `172.28.1.11` is the primary, plain2 `.12` and plain3 `.13` are standbys cloned with `pg_basebackup -R`. Nothing promotes a node by itself. Credentials are `app`/`app` (database `app` with the same `writes` table) and `replicator`/`replicator`; there is no repmgr user or database. `plain.sh up` always throws the old cluster away and starts a new one, which takes about 6 seconds, because there is no repair. `plain.sh promote <node>` runs `pg_promote()`, also while the old primary still runs. Both clusters can run at the same time.

`testenv/watch` prints a line only when the primary, the nearest node or the write result changes. With `-write` it inserts through `Pool.InTransaction` at every poll and shows which node accepted the row.

`testenv/integration_test.go` drives the cluster through `cluster.sh`. Each test starts with `cluster.sh up`, which waits for a healthy cluster, and finds the current primary by asking the nodes directly, so it works whichever node is primary. Tests that cause a failover run `heal` and `repair` in cleanup, which leaves the cluster healthy for the next run with a different primary. `TestFailoverIgnoresOldPrimary` takes about 70 seconds and `TestWritesFollowFailoverQuickly` about 40. `TestNearestSkipsLaggingStandby` takes about 5: it uses `delay` to make one standby the nearest node, pauses replay on it with `pg_wal_replay_pause()`, and writes a few MB of WAL. It connects to the nodes with `execSQL`. `newConnector` closes the connector in `t.Cleanup` and logs through `t`, so the log shows up for failed tests or with `-v`.

`testenv/plain_test.go` has `TestSourceWithoutRepmgr` (about 13 seconds): a connector with a `listSource` over the plain cluster, checking as `app` with `WithoutCheckOverride("dbname")`. It adds a node to the list, promotes plain2 while plain1 still runs, expects plain2 as primary and plain1 unavailable with a split brain error, writes through `Pool`, then drops plain1 from the list. It leaves the cluster in that state; the next `plain.sh up` starts over.

## Architecture

**Background monitor (`connector.go`).** `NewConnector` validates the options (`validate`), seeds `initial` with the given DSNs (each with `NodeID: InvalidNodeID`) and starts `run()` in a goroutine (`start`). `NewConnectorWithSource` does the same with a `NodeSource` instead of seeds (see below). `run` alternates `check` and `wait` until `Close` cancels `c.ctx`. That context also cancels a check in progress; `logCheckError` keeps the resulting errors out of the log. `run` closes `c.done` when it returns, and then `Primary`/`Nearest`/`WaitFor*`/`Refresh` all report `ErrClosed`. Each `check` runs `checkListed` when there is a source, and `checkRepmgr` otherwise. Both return the results, `primaryIdx` and the removed nodes; `check` then does the rest of step 3. `checkRepmgr`:
1. Calls `checkNode` on every known node in parallel (`collectInfos`). It uses the seed DSNs until the initial scan is complete and the previous `nodes` after that. `checkNode` connects and measures connect latency (`connect`). In one query (`queryState`) it asks the node whether it is in recovery, which timeline it writes WAL on, and its WAL position as a byte count (the replay position for a standby). The position goes in the unexported `NodeInfo.lsn`, with 0 meaning unknown. Then it selects all rows from `repmgr.nodes` with `pgx.CollectRows`, and uses them only if it could read all of them, so a failed read never leaves a node `Avail` with a partial list. A node that doesn't end up `Avail` gets a `LastError` saying why.
2. Collects any node IDs found in those rows that were not checked yet, and checks them too. During the initial scan the results for the seed DSNs are thrown away and replaced by the results for the discovered nodes, which have real node IDs.
3. Picks `primaryIdx` with `selectPrimary` (see below). If there is a primary, `withoutRemoved` drops the nodes that the primary's own copy of `repmgr.nodes` doesn't list, because they were unregistered, and bumps `removals`. `setLag` sets each `Avail` node's `LagBytes`, which is the primary's position minus the node's, clamped at 0. It is -1 when unknown and for every node when there is no primary. Then `selectNearest` picks `nearestIdx`, the `Avail` result with the lowest `Latency`. With `Options.MaxLagBytes > 0` and a primary, it skips nodes whose lag is over the limit or unknown. The primary's lag is 0, so it is always a candidate. It swaps them into `c.nodes` (unexported; callers get copies from `Nodes()`) under `mu` together with `checksFinished++`, then calls `relay.Broadcast` to wake any `WaitForPrimary`/`WaitForNearest`/`Refresh` callers. `initialScanComplete` becomes true only once a nearest node exists. Without a primary or nearest node, `Primary()`/`Nearest()` return `NodeID: InvalidNodeID` with `LastError` set to `ErrNoPrimary`/`ErrNoNode` (`errors.go`), and `IsNodeError` counts both as node errors.

**Node source mode (`source.go`).** With a `NodeSource`, `checkListed` gets the list through `sourceList` at the start of every check, with `FetchTimeout`. `validateNodes` rejects a list with `InvalidNodeID` or a repeated ID. On an error or a rejected list, `sourceList` logs it and returns `c.listed`, the last valid list (only `run` touches it; empty until the first success). Every node of the list becomes a `NodeInfo` with `NodeID`/`NodeName`/`Location`/`ConnInfo` from it and `Active=true`, and the other `repmgr.nodes` fields empty. `checkListedNodes` checks them in parallel and keeps the list order. `checkListedNode` uses the same `connect` and `queryState` as `checkNode`, but never reads `repmgr.nodes`: a node is `Avail` if both work, and `IsPrimary` if it is not in recovery. The nodes in `c.nodes` that the new list doesn't contain are the removed ones, independent of the primary, so `removals` is bumped and `Pool` closes their pools. `selectPrimary`, `setLag` and `selectNearest` are shared with the repmgr mode. There is no initial scan: the IDs are real from the start. `Options.WithoutCheckOverride("dbname")` lets the check use the conninfo's database instead of `repmgr`. The check query needs no special privileges.

**Scheduling and `Refresh`.** `wait` waits until `CheckInterval` after the start of the previous check, or `RetryInterval` (default 1 s) after it while there is no primary. A token in the `refresh` channel cuts the wait short, but never to less than `RetryInterval` after the previous start. `Refresh` sets its target to `checksStarted+1`, because a running check may have started before the caller's error. It puts a token in the channel (both under `mu`) and waits until `checksFinished` reaches the target. `run` increments `checksStarted` and drains the token under `mu` at the start of each check, so all `Refresh` calls made before a check starts share it.

**Availability rule.** With repmgr, a node gets `Avail=true` only if its own row (matching `NodeID`) shows up in the `repmgr.nodes` it returned, with `active=true`. Connecting and querying successfully is not enough. A seed DSN has `InvalidNodeID`, so it can never be `Avail` itself; it only serves to discover the real nodes. `selectPrimary` can also turn `Avail` off again (see below). With a `NodeSource`, connecting and querying the state is enough.

**Primary selection (split brain).** A node has `IsPrimary=true` if its own row says `type=primary` and the node is not in recovery (with a `NodeSource`, if it is not in recovery). After a failover, an old primary that is still running keeps saying that about itself. This happens when it is cut off from the other nodes, or when it can reach them again but hasn't been rejoined yet. Promotion always moves a node to a new, higher timeline, so `selectPrimary` picks the `Avail`+`IsPrimary` node on the highest timeline. The node ID only breaks a tie, which keeps the choice independent of the order in which the checks finished. Every other node that claims to be primary gets `Avail=false` and a "split brain" `LastError`, so it can't be the nearest node either, and the connector logs an error at every check. `TestFailoverIgnoresOldPrimary` in `testenv/integration_test.go` covers both cases, `TestSourceWithoutRepmgr` in `testenv/plain_test.go` covers it without repmgr, and `TestSelectPrimary` covers the rule itself.

**Two override maps (`options.go`).** The stored `nodes` keep the raw `conninfo` from `repmgr.nodes` or the source. Overrides are applied only at use time. The `With*Override` methods copy the map before changing it, and `NewConnector` copies both maps, so copies of `Options` never share them.
- `CheckOverrides` are applied when the connector itself connects to check a node. `NewOptions` seeds them with the repmgr user, the password and `dbname=repmgr`. `WithoutCheckOverride` removes a key, so that the node's own conninfo value applies.
- `AppOverrides` are applied only when a `NodeInfo` is returned from `Primary()`/`Nearest()`/`Nodes()` (by `forApp`), and so also from `WaitFor*` and `Pool`.

**DSN handling (`dsn.go`).** Only key=value connection strings are supported, not `postgres://` URLs. `ParseDSN` follows pgx's rules: values can be in single quotes, and a backslash escapes a quote or a backslash (other backslashes are kept). It returns an error for malformed input, and its errors never contain the string, because it may hold a password. `BuildDSN` sorts the keys and quotes values that are empty or contain a space, quote or backslash, so a DSN that has been through `ReplaceInDSN` is normalized and deterministic. `NewConnector` panics on a seed that doesn't parse; `checkNode` sets `LastError` for a conninfo that doesn't. `dsn_test.go` checks that pgx reads what `BuildDSN` writes.

**Pools (`pool.go`, `transaction.go`).** `Pool` wraps a `Connector` and lazily creates one `pgxpool.Pool` per `NodeID`, configured from `DBPoolConfig`. `DBPoolConfig.ApplyTo` copies only the positive fields. The others keep pgxpool's value, which is its default or the `pool_*` setting from the DSN, so `DBPoolConfig{}` is valid. `GetPool` returns the node's `LastError` for a node that isn't `Avail` (for example `ErrNoPrimary` from `PrimaryPool`). It replaces a node's pool when its `ConnInfo` changed. When the connector's `removals` count has changed, it also closes the pools of nodes the connector no longer knows. Either way the old pool is closed in a goroutine, because `pgxpool.Pool.Close` waits for acquired connections. Pools of nodes that are only temporarily unavailable are kept. `Pool.Close` closes all pools but not the connector. `ConnectPrimary`/`ConnectNearest` return a `*pgxpool.Conn` that the caller must `Release()`. `InTransaction` always runs on the primary: it commits if the callback returns nil, rolls back otherwise, and returns the commit error. When `ConnectPrimary`, `ConnectNearest` (both through `acquire`) or `InTransaction` fails with `IsNodeError(err)` (`errors.go`), they call `Refresh` with the caller's context before returning the error. That includes `GetPool` failing with `ErrNoPrimary`/`ErrNoNode`, so a caller's retry loop waits for the next check instead of spinning. They never retry.

**Logging.** The connector logs through `c.Logger()`, which returns `Options.Logger` (set it with `WithLogger`), or `slog.Default()` when that is nil. `NewOptions` leaves it nil. The fallback looks up `slog.Default()` each time it logs, so a later `slog.SetDefault` still applies. `InTransaction` in `transaction.go` has no connector, so it logs rollback errors through `slog.Default()`.
